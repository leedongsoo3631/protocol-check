# 의전 체크 — 구글 플레이 등록 준비물과 순서

> 이 폴더(store/)에 등록에 필요한 파일과 문구가 모두 들어 있습니다.
> 직접 하셔야 하는 일은 **①개발자 계정 만들기 ②서명키 등록 ③콘솔에 올리기** 세 가지뿐입니다.

## 0. 어떤 방식으로 올릴지 (중요)

| 방식 | 누가 받나 | 조건 | 추천 |
|---|---|---|---|
| **내부 테스트** | 이메일로 지정한 직원(최대 100명) | 심사 거의 없음, 바로 배포 | ✅ 직원 전용이면 이것으로 충분 |
| 비공개 테스트 | 지정한 그룹 | — | 공개 출시 전 필수 단계 |
| 프로덕션(공개) | 누구나 검색 | 개인 계정은 **비공개 테스트 12명 이상 · 14일 연속** 후 신청 | 나중에 필요할 때 |

- 2023년 11월 13일 이후 만든 **개인** 개발자 계정은 공개 출시 전에 비공개 테스트(12명·14일)를 거쳐야 합니다.
- 내부 테스트는 이 조건이 없고, 계속 내부 테스트로만 운영해도 됩니다.
- 구청 **기관(조직) 계정**으로 만들면 12명·14일 조건이 없지만, D-U-N-S 번호가 필요합니다.

## ⚠️ 올리기 전에 꼭 정할 것 — 기본 공유 서버
지금 앱에는 **중구청 공유 서버 주소가 기본으로 들어 있어**, 설치하자마자 실제 명단(사진·이름)이 보이고 체크도 됩니다.
- 플레이에 올리면 구글의 **자동 점검 로봇(사전 출시 보고서)**이 앱을 이리저리 눌러 볼 수 있어, 실제 행사 중에 엉뚱한 도착 체크·채팅이 생길 수 있습니다.
- 방법 A(권장): 플레이용은 기본 서버를 빼고, 직원은 **메뉴 → 담당자 초대하기** 문구를 붙여넣어 연결 — `web/index.html`의 `DEFAULT_API` 한 줄만 비우면 됩니다(Claude에게 “플레이용으로 기본 서버 빼 줘”라고 하면 됩니다).
- 방법 B: 기본 서버를 둔 채 올리되, Play Console → 테스트 및 출시 → **사전 출시 보고서 → 설정에서 끄기**.

## 1. 개발자 계정 만들기 (직접, 약 15분 + 신원 확인 1~2일)
1. https://play.google.com/console 접속 → 구글 계정 로그인
2. 계정 유형 선택(개인/조직) → 등록비 25달러 결제 → 신원 확인(신분증)
3. 개발자 이메일 · 웹사이트 칸에는 아래 개인정보처리방침 주소를 써도 됩니다

## 2. 서명키 등록 (직접, 2분) — 이게 있어야 플레이용 파일(AAB)이 만들어집니다
1. GitHub 저장소 → **Settings → Secrets and variables → Actions → New repository secret**
2. 이름 `KEYSTORE_BASE64` / 값: 받아 두신 `KEYSTORE_BASE64.txt` 파일 내용 전체 붙여넣기
3. 이름 `KEYSTORE_PASSWORD` / 값: `의전체크_서명키_정보.txt` 에 적힌 비밀번호
4. **Actions → 앱 빌드 → Run workflow** → 끝나면 Releases 에 `uijeon-check_playstore_v1.0.N.aab` 가 생깁니다
5. ⚠️ 서명키 파일과 비밀번호는 잃어버리면 앱 업데이트를 못 하니 USB·클라우드 두 곳에 보관하세요

## 5. 앱 콘텐츠(정책) 답변표

**개인정보처리방침**: 위 3번 주소

**앱 액세스 권한**: “모든 기능을 특별한 액세스 권한 없이 이용 가능” 선택
- 처음 실행하면 이름만 입력하면 됩니다(로그인 없음)
- 설정에서 공유 서버 주소 칸을 비우고 저장하면 휴대폰 안에서만 쓰는 모드(비밀번호 없음)로 모든 화면을 확인할 수 있습니다
- 심사용 메모에 적을 내용: “편집 기능 비밀번호가 필요하면 설정의 공유 서버 주소를 지우고 로컬 모드로 시험해 주세요(비밀번호 없음).”

**광고**: 광고 없음

**콘텐츠 등급(설문)**: 카테고리 “유틸리티, 생산성, 커뮤니케이션 또는 기타”
- 폭력·성적 콘텐츠·도박 등 모두 “아니요”
- 사용자 간 상호작용(채팅): “예” — 같은 공유 서버를 쓰는 업무 담당자끼리만 메시지를 주고받음
- 위치 공유: “예”(동의한 경우에만, 같은 서버 담당자끼리)

**타겟층**: 만 18세 이상

**데이터 보안(Data safety)**
| 항목 | 답변 |
|---|---|
| 데이터를 수집하거나 공유하나요? | **예** — 이용자가 공유 서버를 쓰면 이용자가 지정한 구글 시트로 전송됨 |
| 전송 중 암호화 | 예 (HTTPS) |
| 삭제 요청 방법 | 앱에서 직접 삭제 가능(전체 명단 삭제·채팅 비우기·위치 공유 끄기) |
| 위치 – 정확한 위치 | 수집, 앱 기능(담당자 위치 지도), 선택사항(동의 시), 처리만 하고 공유 안 함 |
| 개인 정보 – 이름 | 수집, 앱 기능(체크 기록·채팅 표시) |
| 사진 및 동영상 – 사진 | 수집, 앱 기능(참석 인사 사진·현장 사진첩, 앱 안 카메라로 촬영), 선택사항 |
| 메시지 – 기타 인앱 메시지 | 수집, 앱 기능(담당자 채팅) |
| 앱 활동 – 기타 사용자 생성 콘텐츠 | 수집, 앱 기능(명단·일정·좌석) |
| 제3자 공유 | 없음 (개발자 서버 없음, 광고·분석 SDK 없음) |

**포그라운드 서비스 신고(dataSync)** — “화면이 꺼져 있어도 알림” 기능
- 기능 설명: 사용자가 설정에서 직접 켜면, 행사 진행 중 다른 담당자의 도착 체크·채팅·일정 변경을 공유 서버(사용자의 구글 시트)와 동기화해 알림으로 알려 줍니다. 상단에 진행 중 알림이 항상 보이며 “알림 끄기”로 바로 멈출 수 있고 12시간 뒤 자동으로 멈춥니다.
- 사용자 영향: 지연·중단되면 담당자가 VIP 도착을 늦게 알아 의전 대응이 늦어집니다.
- 사용 사례: “네트워크 전송: 업로드 또는 다운로드”
- 동영상: 설정 → “화면이 꺼져 있어도 알림” 켜기 → 화면 끄기 → 다른 휴대폰에서 도착 체크 → 알림이 오는 장면을 30초 정도 녹화해 유튜브(일부 공개)에 올리고 링크 입력
- ⚠️ 심사에서 이 용도를 거절하면: 이 기능만 빼고 다시 올리면 됩니다(앱을 열어 둔 동안의 알림은 그대로 동작)

**사진·동영상 권한(READ_MEDIA_IMAGES) 신고** — “카메라” 버튼
- 휴대폰 기본 카메라 앱을 모든 기능 그대로 열고, 돌아오면 그동안 찍은 사진을 자동으로 사진첩에 넣기 위해 사용합니다.
- ⚠️ 구글은 사진 전체 접근 권한을 ‘사진 관리가 핵심인 앱’에만 허용하는 편이라 거절될 수 있습니다. 거절되면 이 권한만 빼고 올리면 됩니다 — 그때는 카메라에서 돌아온 뒤 ‘방금 찍은 사진 고르기’ 화면이 자동으로 열리는 방식으로 동작합니다(코드는 이미 대비돼 있음).

## 6. 출시
1. 테스트 및 출시 → **내부 테스트** → 새 버전 만들기 → `.aab` 업로드
2. 출시 노트: `listing_ko.md` 의 “이번 버전” 문구
3. 테스터 탭 → 이메일 목록 만들기(직원 구글 계정) → 저장
4. “테스터 참여 링크”를 직원 카톡방에 공유 → 링크에서 ‘참여’ 후 플레이 스토어에서 설치
